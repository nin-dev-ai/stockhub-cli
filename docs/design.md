# Interface design

## Structure

The interface is a dark, amber-accented terminal workspace. [`App.tsx`](../app/src/App.tsx) stacks the command bar, section strip, quick bar, the active function panel and the status bar. One screen shows at a time: opening a function from the command bar, quick bar, section strip or a link replaces the current screen (there is no tab strip). Each screen keeps its own state in its store, so returning to it picks up where you left off.

## Primary navigation

A strip under the command bar switches between the product's sections: **Explore** (the original terminal), **Strategies**, **Personas**, **Simulation Lab** and **My Portfolio**. Each section opens its screen in the single workspace, so the command bar and the quick bar work everywhere. `sectionOf` in [`functions.ts`](../app/src/lib/functions.ts) assigns every function code to a section.

## Strategies screen (`STRAT`)

A filter rail (search, sort, type, risk level, robustness, and *Test against ETFs*: an equity ETF replacing SPY and a defensive ETF replacing SHY, with a reset and an "only strategies that changed" filter) beside a grid of strategy cards, with a basket bar at the bottom and a drawer on the right. The default sort ranks the robustness verdict first, then Sharpe, then drawdown, never return alone. Cards show CAGR, the difference from the benchmark, max drawdown, Sharpe, the sample window and a short run id. While the ETF switch is active the header names the swap and counts retargeted and unchanged strategies, and unsaved variants carry an "ETF variant" badge. ETF dropdowns are grouped by asset class and note histories that start after 2004. The drawer shows a four-step flow (data, signal, schedule, orders), a *Run on other ETFs* mapper (one dropdown per ETF the strategy uses, validated before it saves the variant as a draft), a *Spread across several ETFs* picker (core ETFs as toggles plus a dropdown, up to six, equal split; shown only for strategies that trade one main ETF) whose result adds a per-ETF table (combined, each sleeve with its share of the gain, the same rules on the original ETF, buy-and-hold of the same ETFs), a sleeve correlation matrix and a one-line verdict on drawdown, the exact rules and JSON definition, evidence charts and metrics, robustness, a reason for each trade, assumptions with the dataset version, and warnings. Every result is labelled as a historical backtest. Metrics the sample cannot support show "n/a" with the reason.

## Simulation Lab screen (`LAB`)

The canvas opens on a **Plan** tab (before Backtest, Allocation and Projection), described below; the Backtest runs automatically so it is always live. An inputs pane (starting amount, existing holdings, monthly contribution, *Look forward* (projection years), *Look back* (years of history to test, with an *All available* checkbox and a hint that signals use the history before the window and that projections need 5 years), a *Run on other ETFs* section, folded unless the plan already uses another ETF, holding *Run on ETF* with the core ETFs as radio rows and a dropdown for the rest and *Spread across more ETFs* toggles that run SPY-based strategies on several ETFs side by side, basket, risk objective, weight cap, advanced assumptions) beside a canvas headed by a step line (*✓ Strategies (n)* → *Check the plan* → *Save* → *Follow in My Portfolio*, each a button), *Save Plan* and *View Methodology*. Allocation and Projection run the first time their tab opens. Save Plan works as soon as the backtest is done: without a projection for the current inputs it shows *Preparing…*, runs one, then opens a drawer to name the plan (prefilled from the fall limit, such as "Balanced plan, 30% fall limit"; Enter saves) and choose paper or manually reported tracking. Long-running actions show progress and can be cancelled. Every result carries a label: *Historical backtest*, *Historical weights* or *Future simulation (model-based)*. The projection fan chart labels the 10th, 50th and 90th percentiles and states that the lower line is not a worst case. Weight overrides must sum to 100% and are previewed before they apply. With no basket, the Lab explains the next step and links to Strategies.

**Plan tab.** A header (strategy count, one badge per job with its share of the plan, a *Worst fall I'd accept* percentage, a *Rebalance* menu, *Build me a plan* and *Add a strategy*), then a table with one row per strategy: job badge, name, what it holds today, an editable weight (changing one rescales the others so the total stays 100%), CAGR, worst fall, Sharpe and a remove ×, and a final row for the plan together (its worst fall turns red past the limit). Under it: where the weights came from with *Equal weights* and *Optimizer weights*, and, unless the rule is every day, a line giving the plan's CAGR and worst fall under the chosen rule next to the idealised every-day figures; two bar lists, *What the plan holds today* by ETF and *By asset class today*; the concentration check below them says it is the average over the backtest; and *Does this plan make sense?*, a list of ✕ issues, ! warnings and ✓ good signs, each with a one-line reason and, where possible, a fix button (remove the weaker of two near-copies, add a core or diversifier). *Build me a plan* and *Add a strategy* open a panel above the table: the proposal (jobs, a one-line *Why* per strategy, weights, combined result, whether it is within the limit, the largest asset class on average, an *Out-of-sample check* block with a green or red edge giving the one-line verdict and the later-years CAGR and worst fall for these weights, an equal split and the best single strategy, *Use this plan* / *Cancel*) or the catalog ranked by fit with the worst fall now and with the strategy at 25%. With an empty basket the Lab offers the fall limit, *Build me a plan* and *Pick strategies myself*.

## My Portfolio screen (`PORT`)

A rail lists paper plans, manually reported records and broker-reported records in separate groups, with a form to record existing holdings without a plan an *Interactive Brokers (read-only)* entry that opens the broker panel in the main area, and a *Paper orders* link to the `ORD` screen (it is not on the quick bar, which would overflow at 1440 px): read-only and connection badges (paper account in cyan, live account marked read only), setup steps when the gateway is not running (including the macOS port 5000 note), a login link when it needs a login, account choice, net liquidation and cash, a positions table with a *Tracked* column giving the reason a position is left out, and *Sync into* (a new broker-reported portfolio or an existing one) with the result in one line. The main area has three tabs. **Plan vs Observed** shows value, net contributed, gain and cash tiles; a timeline with the original plan's 10th–90th percentile band and median, planned and actual contributions, the observed value and the latest reforecast; a table that splits observed minus planned median into contribution difference, projection error, allocation difference and FX (not applicable); and holdings against plan targets. Paper plans add contribution and rebalance actions; trades are previewed and need confirmation. **Ledger** adds, filters, deletes and exports entries, and refuses entries that would overdraw cash or sell units not held. **Snapshots** lists every snapshot with its integrity badge, inputs, versions and percentiles, and runs reforecasts over selectable horizons. Every view carries its mode badge: *Paper (hypothetical)* in cyan, *Manually reported · not broker-verified* in amber or *Broker-reported · IBKR, read-only* in green. Save Plan in the Lab offers all three modes.

## Personas screen (`PERS`)

A rail with three groups of personas (fund managers · 13F, corporate insiders · Form 4, US House members · PTR) with checkboxes and a remove control for added ones, an add form (Insider: name and ticker; Fund: display name and SEC CIK; House: a search of members by name or district, each result showing its report count, followed on click), and a source note. The main area has a filter bar (ticker or company search, All / Buys / Sells, *Buys and sells only*, on by default, which hides grants, exercises, tax withholding and gifts), one summary card per followed persona (click to filter the table), and a merged table sorted by date: date (quarter for funds), persona, action (green buys, red sells), security, shares, price, value, detail and a filing link. The table has a *Trade date* and a *Public (UTC)* column: the SEC's acceptance time for EDGAR filings (hover for the form), the filing date for House reports, or a dash for a quarter-end 13F row; rows sort by when the public could first see them. Schedule 13D/G rows are cyan *Stake report* rows (percent of the class, shares, holders) and are shown even with *Buys and sells only* on. Cathie Wood's card adds a line for ARK's daily trades (count in the last 30 days, newest trade date, the official holdings file's date) and her daily rows read *Bought (ARKK)* or *Sold (ARKQ)* with the fund's weight in the detail column. Each persona with SEC identities has a freshness block: a green *N new* badge for filings accepted since the last look, the newest filing's form, time and age, for funds the 13F filing date as the portfolio table's source, the last check time, and a red message if the SEC could not be reached. Without `STOCKHUB_SEC_CONTACT` an amber banner explains how to turn live filings on. The rail ends with *Alert me to new filings* and one line of status (how often it checks, waiting for permission, blocked, or on); with alerts on, each live card shows *Alerts on* / *Muted*, and the tab title reads "(N) StockHub" while N new filings are unseen. A *Since public* column shows each trade's move since the first close a follower could trade at, with the difference from SPY in brackets, green when the trade was on the right side (a buy that beat SPY, a sale of a stock that then trailed it) and red otherwise; hover for the dates. Cards add a one-line summary. The value column shows a House trade's amount range; the detail column is clamped to two lines with the full text on hover. House cards show reports found, buys and sells, the latest trade date, links to scanned or unread reports, and a *Backtest copying* toggle (fund cards: *Backtest copying the 13F*; insider cards with purchases too) that opens a panel above the table: badges (historical backtest, experimental, not a recommendation), the copy rule in one paragraph, a one-line verdict on the reporting-delay cost, a table of the filing-date copy, the trade-date copy and SPY (total return, CAGR, drawdown, Sharpe, final value), a growth-of-100 chart, the stocks copied and left out, flags and caveats; a note under the cards states the disclosure limits. Fund cards show the quarters compared and holding count; a *Stale* badge marks a latest filing more than nine months old. A card with nothing to show says why.

## Paper Orders screen (`ORD`)

One scrolling page under My Portfolio. A header with badges (paper accounts only, each order needs your confirmation, trading on or switched off) and a red *Kill switch* button; a paragraph stating the limits. When switched off, a red box blocks everything until the user ticks "I want to send paper orders again" and turns trading back on. Account picker with a paper or live badge (live: a red line saying orders are refused), net liquidation, cash and today's sent total against the daily cap. *Rebalance to plan* picks a saved plan and shows its targets, notes (holdings left alone, scaled purchases, missing prices) and a hint to send sales first; the order table shows each order (green buys, red sells), estimated price and amount, the reason, a *Limits* cell (green "Within limits" or the red reasons) and a steps cell that walks through *Preview with IBKR* → commission and equity change → *Send…* → "Buy 20 SHY at market in paper account DU…?" *Confirm and send* / *Cancel* → IBKR's own questions verbatim with *Yes, send it* / *No, don't send* → the placed order id and status. Then open orders, the two caps with *Save limits*, and the audit log (newest first, UTC times) with *Export JSON*.

## Copilot panel

A **Copilot** toggle at the right of the primary navigation opens a 360px panel beside the active screen; the open state persists, the conversation does not. A strip names what the Copilot can see: the screen and, only for that screen, the open strategy, Lab results or portfolio. Answers show a title, short paragraphs and lists, a *Figures traced to engine* badge when they quote results, and a sources line. Withheld answers carry a red *Withheld* badge. An ETF variant or drafted strategy appears as a card with a diff against the curated strategy it resembles (or the strategy it edits), the editable JSON with generated rules, and Save draft / Cancel; nothing is saved without that click. A plan request ("build me a plan with a 25% fall limit") shows a short explanation and a *Test the catalog and propose a plan* button; only then does the Plan tab's proposal panel appear inside the card (jobs, weights, combined result, within or outside the limit) with *Use this plan*, which replaces the strategies and weights, opens the Lab and leaves an *Undo* on the card. A Lab-input proposal shows a table of current and proposed values with *Apply to Lab*, which applies them and opens the Lab. A persona answer shows a *Follow* button that follows the persona and opens the Personas screen, or *Open Personas* when the person must be added there or cannot be followed. Suggested prompts change with the screen and with what has been calculated. Answers with a screen to open (Paper Orders, My Portfolio) show one *Open …* button. With the optional LLM phrasing on, an answer shows *Phrasing…* while Claude rewords it, then *Phrased by Claude · figures checked* in cyan with a *Show the computed answer* toggle, or *Rule-based wording* (hover for the reason) when the rewording failed a check; the footer names the model.

## Interaction conventions

- Entering a ticker alone opens `INTEL` for that symbol.
- Commands accept a symbol followed by a function code, such as `AAPL GP`; the parser also accepts a function code followed by a symbol.
- A symbol-requiring function can use the active symbol when entered by itself.
- The command bar provides autocomplete and keyboard navigation. The [README](../README.md#the-function-codes) lists user-facing shortcuts.
- The workspace shows one screen at a time and remembers the last one in browser storage; older saved workspaces with several tabs keep only the screen that was showing.

## Visual conventions

The visual system is defined in [`app/src/index.css`](../app/src/index.css) and [`app/tailwind.config.js`](../app/tailwind.config.js). Reuse the existing terminal colors, type scale, panels, and status treatments when adding a screen. Charts use `lightweight-charts` where appropriate.

## Content conventions

Use concise labels, units, and date ranges for financial values. Distinguish missing data from zero. Show loading and provider error states in the panel where they occur. Describe INTEL outputs as rule-based signals, with the underlying thresholds available in [`signals.ts`](../app/src/lib/signals.ts).

On multi-request market screens (`CC`, `WEI`, `CRYPTO`, `FXC`), a shared notice ([`QueryFailureNotice`](../app/src/components/QueryFailureNotice.tsx)) reports how many requests failed, shows the first error, and offers retry, so a failed request is not mistaken for missing data.

On INTEL, show a data error with retry when the quote or profile request fails and there is no usable identity or price. If some requests fail while other data loads, label the scorecard as incomplete and offer retry.
